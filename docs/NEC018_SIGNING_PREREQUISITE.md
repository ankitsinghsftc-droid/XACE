# NEC-018 signed-artifact identity prerequisite

Code-confirmed blocker, not a failed signing attempt. No certificate is currently available and no private key/certificate store was changed.

Python native_executor_contract.py validate requires two independent output hashes to equal executable_sha256, and shipping.required_files binds that exact final executable. admit rehashes the executable against a host-pinned receipt digest. Rust player-launcher/src/native_release.rs verify_executor enforces the same reproducibility identity and strict receipt keys. Authenticode signing changes PE bytes; changing only a checksum or rewriting the historical unsigned build outputs would violate those contracts. Existing v1 has no separately represented signing derivation. The NEC018 unsigned handoff refuses any claim that it closes REL04.

Required implementation within NEC-018 before signed release:

1. Design/version an explicit artifact derivation retaining the two independently reproduced unsigned build identities and separately binding final signed bytes, approved signer, signing/timestamp policy and the trusted source/build receipt. Review publisher authority outside an untrusted project. Preserve legacy v1 unsigned compatibility; reject unknown/malformed/unauthorized derivations.
2. Implement matching Python creator and Rust native-host admission. Verify the approved signed artifact using actual Windows trust/certificate evidence; do not treat a certificate subject or a JSON boolean as publisher authentication. Preserve capability/ABI/system/state/replay checks and out-of-band trusted receipt pins.
3. Order creator packaging correctly: sign executor/launcher only in new copies; reissue final package/support/receipt hashes and native profile pins; approve changed native source explicitly; build/cook, sign controlled native executables under the reviewed publisher policy, then generate final cooked/native file inventories. Preserve vendor signatures/rights as required by the approved distribution inventory. Never mutate sealed unsigned artifacts.
4. Rerun actual signed admission, native gameplay/resources/projections, tamper/refusal, relocation/offline/cleanup and clean-machine SmartScreen/trust checks. Re-signing/timestamps cannot relabel old byte-hash evidence as signed evidence. Save identities currently include executor hash, so signed/unsigned transitions must retain originals and use explicit tested migration or unchanged refusal.

Planning estimate: roughly1-2focused engineering days for the versioned derivation/admission/packaging integration, plus1-2days for real signed three-engine verification on the declared hardware, after a suitable authorized certificate/service and clean test environment exist. This is an estimate, not a deadline; external procurement/availability is unbounded. It fits the existing NEC-018 scope and does not add/reorder roadmap tasks. Do not mark NEC-018 complete while this or any external gate is open.
