# NEC-018 signing and delivery workflow

Implemented code is not publisher certification. No XACE certificate, private key, trust-store change, signing purchase, public upload or external deployment is performed by these tools. Existing unsigned builds and evidence remain unchanged. The existing handoff-b archive remains unsigned; never rename it as a signed release.

1. Reproduce the executor as before and preserve both independent unsigned outputs/receipts. Build the new native launcher and preserve its exact source/build identity and unsigned SHA256. Obtain the owner's separately approved publisher policy: xace.publisher_policy.v1, trust_policy windows_authenticode_cached_chain.v1, and a sorted allowlist of SHA256 DER signing certificate identities. A SHA1 thumbprint or subject string is not this identity.
2. The authorized operator signs NEW copies of the unsigned executor and launcher through the approved certificate/HSM/service, using the approved SHA256 signing and timestamp policy. Preserve signer/timestamp/signing-service logs outside source control with secrets excluded. Do not import a test root, bypass Windows security or rewrite unsigned compiler output hashes. Current revocation/publisher approval remains an explicit release check; runtime trust checks use cache-only OS Authenticode chain/integrity and require a verified timestamp. Offline chains must actually pass on the declared fresh-machine profile.
3. Run `python tools/nec018_finalize_signed_release.py --help`. Supply the trusted unsigned common-release pin, independently approved publisher-policy digest, unsigned launcher build pin, separately signed PE copies and a trusted newly built native-verifier path/hash. Use a new persistent output. The tool verifies byte-preserving PE derivation and actual Windows signer/timestamp identity, preserves CGS/plan/presentation/sidecars/notices, regenerates executor/package/common-release identities and runs native v2 admission. It does not execute the signed game or grant release approval.
4. In a NEW reviewed native source copy, configure that common release and its exact release/launcher hashes through the existing native setup/materialization and source-approval flow. Godot, Unity and Unreal consume these hashes and delegate common admission to the launcher; their code does not hardcode a v1 common receipt. Never silently overwrite source approvals. Run the existing checked native build/export/cook workflow into a fresh output. Preserve its original unsigned build receipt and file inventory. XACE source/scene approvals still apply.
5. The authorized operator signs NEW copies of the required first-party engine game executables. Preserve existing vendor signatures and applicable vendor terms. For the current Unreal fixture both the bootstrap and actual project executable need their declared signing coverage; the bootstrap alone is insufficient. Keep the common signed runtime/launcher intact. Do not re-sign vendor DLLs under the XACE publisher without specific authority.
6. Run `python tools/nec018_finalize_native_delivery.py --help`. `finalize` accepts the independently reviewed unsigned native inventory digest, approved publisher-policy digest and an explicit portable-relative-path to signed-copy map. It creates another new native delivery copy, changes only the selected PE signing fields/certificates and, for Unreal, reissues XACEBuild.json hashes. The old cooked/source/build receipts are preserved as originals; XACE-SIGNED-DELIVERY.json records the derivation and exact final inventory. `verify` requires that receipt's independently supplied SHA256 and checks actual Windows signatures, unchanged original machine code, unrelated-file preservation and cooked inventory. Both report derived_not_certified.
7. Run `python tools/nec018_prepare_signed.py --help`. Its separately pinned xace.nec018.signed_handoff_inputs.v1 configuration supplies the original unsigned handoff root/digest for context, approved publisher policy, trusted native verifier path/hash and all three new signed delivery roots/pins, relative common-release roots/pins and required engine executable paths. The tool verifies real v2 common admission and signed native derivations before creating a new v2 archive. Prior native_proof_sha256 values are explicitly unsigned context; they never become signed-gameplay evidence. Every gate still starts OPEN.
8. Run the new archive's pinned PowerShell runner for fresh signed native gameplay/resource/input/cleanup probes. Its v2 mode requires valid timestamped embedded signatures with approved signer DER on required native entries and common launcher/runtime. Complete relocation, offline, failed/tampered/missing-resource, distinct update/rollback/save compatibility and native build checks against those exact final signed bytes. Signed/unsigned executor identity transitions require exact save admission or unchanged refusal; no automatic migration/restoration is implied. Keep all failed attempts. Finally run the mandatory clean-PC and human workflows plus the separate real LAN/Internet/rights checks.

For owner configuration, use the CLI field names above and exact supplied SHA256 identities; no command should contain a private key or password. The signed-handoff configuration is explicit operator input, not untrusted CGS/browser authority. No script disables security or turns a technical signature check into private-alpha/public-release/Steam certification.
