# Provider Token And Cost Accounting

Task 53 defines the provider accounting ABI used by inference telemetry,
prompt benchmark artifacts, and launch certification. The ABI records prompt
tokens, completion tokens, cache tokens, cost, model, tier, latency, request
ID, outcome, retry summary references, and redaction status for each telemetry
event.

## Scope

Accounting rows are generated from `InferenceTelemetryEvent` records emitted by
`InferenceAdapter`. The same exporter is used by:

- `tools/provider_token_cost_accounting_check.py`
- `tools/prompt_corpus_benchmark.py`
- launch certification quick/full checks

Local classifier-only prompt benchmarks do not make hosted provider calls, but
they still emit provider accounting artifacts with zero events and a summary
that records the benchmark case count and `provider_call_count: 0`.

## Accounting Event ABI

Each row uses `xace.provider_accounting_event.v1` and includes:

- `request_id`, `session_id`, and `call_label`
- `provider`, `model_id`, `model`, `complexity_tier`, and `tier`
- `prompt_tokens`/`input_tokens`
- `completion_tokens`/`output_tokens`
- `cache_read_tokens`, `cache_write_tokens`, and `effective_input_tokens`
- `total_tokens` and `total_billed_tokens`
- `cost_cents` and `cost_usd`
- `latency_ms`, `outcome`, `cached`, and `provider_kind`
- retry summary fields: attempts, retries, timeout, rate limit, backoff,
  failure category, user error code, and retry report schema
- `redacted: true`

## Summary ABI

The summary uses `xace.provider_accounting_summary.v1` and aggregates:

- event count and live provider-call count
- request ID counts and missing request ID count
- prompt, completion, cache-read, cache-write, effective input, total, and
  billed token totals
- total cost in cents and USD
- latency totals, average, p95, and max
- counts by provider, model, tier, outcome, and provider kind
- benchmark case count and notes

## Redaction

`packages/inference/src/telemetry_pipeline.py` now has an inference-local
standalone redactor, so inference telemetry does not depend on the Builder
server import path to redact credential-shaped strings. The accounting exporter
applies redaction again before writing JSONL, JSON, or Markdown.

## Local Proof

Run:

```powershell
python tools/provider_token_cost_accounting_check.py --json
```

The checker uses a synthetic provider through the real `InferenceAdapter` and
proves:

- live success records exact prompt, completion, cache, cost, model, tier,
  latency, and request ID fields
- response-cache hits still produce zero-cost accounting rows
- deterministic Tier S shortcuts still produce zero-cost accounting rows
- provider failures still produce request/model/tier/outcome/retry accounting
- credential-shaped labels are redacted in telemetry and accounting artifacts

Prompt benchmark accounting artifacts are generated by:

```powershell
python tools/prompt_corpus_benchmark.py --output target-production-prompt-corpus
```

The benchmark output directory includes:

- `provider_accounting.jsonl`
- `provider_accounting_summary.json`
- `provider_accounting.md`
