# NEC-018 signed artifact contract

Status: implementation in progress, not publisher certification. Historical v1 receipts and sealed outputs remain unchanged.

The new xace.native_executor_build.v2 receipt embeds the complete validated v1 unsigned receipt and its canonical SHA256. The only permitted changes to its outer copy are schema, final executable SHA256 and shipping runtime SHA256, plus an explicit xace.authenticode_derivation.v1 record. Both independent creator build outputs remain the original unsigned hash. No capabilities, source, compiler, system, compatibility or state claims may change during signing.

Host configuration independently pins both receipt digest and xace.publisher_policy.v1: a nonempty sorted allowlist of SHA256 DER signer-certificate identities and the exact windows_authenticode_cached_chain.v1 policy. The corresponding xace.native_release.v2 contains that publisher policy inside the independently approved release digest. v1 releases admit only v1 executors; v2 requires v2 and matching publisher policy. No project-supplied PASS assertion, subject string or SHA1 thumbprint is publisher authority.

Python and Rust call Windows WinVerifyTrust on the exact PE, inspect its verified primary signer DER and a verified timestamp countersigner, require the allowed signer, and rehash bytes around verification. Verification is read-only, has no UI and uses cache-only URL retrieval. It validates the OS Authenticode chain/integrity with no fresh online revocation retrieval; current online revocation/publisher approval and SmartScreen observations remain separate release checks. Missing/untrusted/untimestamped/changed signatures fail closed. Non-Windows hosts cannot admit signed executors. No certificate store, OS trust setting, private key or security policy is modified.

Creator finalization is create-only: validate the trusted unsigned release and file closure, verify separately supplied signed executor and launcher against the explicit publisher policy, derive a v2 receipt, rebuild package hashes using the signed bytes and original CGS/plan/presentation, write a new native release and verify it with the freshly built native host. Native editor approval/source/build/cook inventories must then be reissued explicitly, after final signing. Existing native builds and seals are not patched in place. Save identity changes follow exact admission or unchanged refusal; no automatic save restoration/migration is inferred.

API references: Microsoft [WinVerifyTrust](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust), [WINTRUST_DATA](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-wintrust_data), [verified signer](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-crypt_provider_sgnr). Real publisher-backed XACE signing and final three-engine signed native/clean-machine tests remain mandatory.
