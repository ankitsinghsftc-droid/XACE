# XP-014 — Private session invitation and data acquisition

Decision date: 2026-10-02. Implemented; two-machine acceptance pending.

The installed native launcher is the local trust boundary. It starts one authoritative process for a hosted session and launches the trusted installed Player in external-session mode. A recipient acquires data only. It never downloads or loads the host's executable, DLL, PCK, GDScript or engine project. Its own runtime bytes must match the descriptor runtime hash; the local trusted runtime is copied into the verified data cache to satisfy package inventory validation, but is not launched for the joined Player.

`xace.invite.v1`, encoded as `XACE1-` plus hex JSON, pins a private IPv4 endpoint, opaque token, descriptor SHA-256 and expiry. `xace.session_package.v1` pins the session/incarnation, manifest records, receipt and runtime identity. Requests/responses use `xace.invite_request.v1` / `xace.invite_response.v1`. The service exposes describe, bounded file reads and redeem only. Redemption validates the descriptor pin and consumes a grant atomically. Unused invites expire after 600 seconds; redemption occurs only after full local verification. Admission and readiness still go through XP-011/013: possession of an invite or downloaded package cannot grant live input membership.

Bounds: 4 simultaneous service workers, 8 pending runtime connections, 8 KiB request / 1 MiB response frames, 64 KiB file chunks, 4096 file records, 128 MiB per file, 512 MiB per package and 8 cached package directories. Reads have a whole-frame deadline; acquisition has a 120-second budget. Only admitted JSON/PNG/WAV/BIN data is fetched. Paths, case-folded duplicates, lengths, digests, manifest inventory and receipt pins are checked. Cache directories carry exclusive Windows leases: active Players retain theirs; abandoned inactive caches can be reclaimed under the install lock. Normal failure/leave removes staged data.

The authority binds a selected private/loopback/link-local address, never wildcard/public Internet. `XACE_SESSION_ADDRESS` can select the local private interface. Runtime control is disabled. Builder calls retain local-origin and capability checks; Player command files carry the per-launch token. Windows process jobs own descendants. Closing the host ends its authority; closing a friend releases its client. Ephemeral tickets are removed while append-only authoritative journals remain under `session-history/`. Incremental journal reads preserve readiness across log growth.

One to four human controller IDs are derived from CGS, with distinct ownership and no new actors or gameplay schema mutations. The first reference game merely supplies those ordinary components. Other mechanics use the same session path.

Private-network transport is currently plaintext. Invite possession grants its scoped access; hashes detect mismatched data but do not provide encrypted transport. XP-015 must add authenticated encrypted relay reachability without exposing Builder or creating another authority. No public-network security or NAT traversal claim is made here.

A spent invite cannot be reused. XP-013 reconnect rotates the admitted Player's credential and preserves its canonical identity. Loss of a redemption/acknowledgement response fails closed; there is no durable grant-recovery service in this profile, and a new host session may be required. Slow clients that cannot acknowledge the current baseline remain fenced. Journal retention prepares later debugging/replay work; XP-014 does not implement cross-epoch replay or campaign persistence.
