# XP-013 — session projection acknowledgement and fencing

Accepted 2026-10-01 for the local Windows live-session profile.

The authority owns gameplay state. Clients receive projections for presentation and never restore the authoritative WorldSnapshot. A projection stamp is `xace.session_projection.v1`, scoped by session/incarnation/epoch/generation and identified by baseline UUID, monotonic connection sequence, next simulation tick and exact UTF-8 entity-projection SHA-256. The handshake and live tick snapshot carry `sync`, `sync_json` and `projection_json`; `session_baseline` provides a full replacement outside gameplay tick delivery. An ACK carries `msg_type: baseline_ack` and `stamp_json`. Recovery carries `msg_type: resync_request` and `connection_generation`.

Only the exact outstanding stamp is acknowledged. At an authoritative boundary, an ACK for the current next tick permits required-input membership and the next input request. An older ACK causes replacement with the latest baseline while the peer stays fenced. Existing ready peers do not wait for unready peers. Normal live snapshots also require acknowledgement before the next input request. Five seconds without baseline acknowledgement closes the connection. Catch-up storage is one full baseline per bridge; no historical deltas are queued. Peers that cannot acknowledge a current projection remain syncing, so high-latency liveness is not certified by this local profile.

The client verifies identity, generation, sequence and digest before replacing its projection. Stale/duplicate state is discarded. Gaps and corrupt content fence input and request replacement. Full restoration removes entities absent from the snapshot and replaces complete component maps. Transport counters and UUIDs never enter deterministic gameplay state.

Each admission rotates the reconnect credential and increments generation. A credential is scoped to one session, peer and controller. Reconnect requires disconnection, exact gameplay compatibility and the same canonical player entity. The host clears disconnected-generation input and anti-replay sequence state but preserves rate windows. Same-generation resync does not reset anti-replay history. Old sockets cannot supersede an active generation. An ACK lost before the rotated token is received leaves the client fenced; XP-014 defines broader token expiry/redemption UX.

`session.projection.v1` is a negotiated transport feature, not a world semantic capability. World Contract types, gameplay nouns and mechanic executors are unchanged. Unity/Unreal presentation clients must implement this generic protocol before XP-017 can claim actual cross-engine play. Ruleset mutation in XP-018/019 must fence old-epoch projections and inputs using this identity; future delta optimization must retain baseline IDs and gap recovery.
